# 改造说明：从「一份克隆快照」到「可配置模板」

本文记录这次改造做了什么、为什么这么做，以及过程中发现的问题。
面向的读者是要维护这份仓库的人；只想用的话看 `README.md` 就够了。

---

## 1. 改造前的状态

原仓库是 `storytelling.noomoagency.com` 的静态克隆，加上一份**没有生效的中文化**：

- `index.html` 里的预渲染文案被改成了中文；
- 但同样的文案在 `_nuxt/CbdjwYMp.js`（引擎 chunk）里还是英文；
- Vue **注水（hydration）** 的瞬间，JS 里的英文把 DOM 里的中文覆盖回去。

也就是说：**页面加载时闪一下中文，然后变回英文**。浏览器控制台还会报注水不匹配警告。

同时存在的问题：

| 问题 | 说明 |
|---|---|
| 文案散落 | 24 处内容分布在 HTML、页面 chunk、引擎 chunk 三个文件的十几个位置 |
| 无法配置 | 想改一句话就得在 3MB 的压缩 JS 里搜字符串 |
| `config.js` 404 | HTML 里引用了一个不存在的 `./config.js` |
| 站内路由全死 | `/cases/:slug`、`/contacts` 的 chunk 克隆时没抓下来 |
| 渐变文字失效 | `lg:lines-text-gradient` 在编译好的 CSS 里根本不存在 |
| 拼写错误 | `lg:hiddn`、`lg!w-400` 等无效类名 |

---

## 2. 改造思路

**核心约束：`src/_nuxt/*` 是编译产物，源码不可得，不能重写，只能精确替换。**

`CbdjwYMp.js` 是 Vue 运行时 + Three.js + GSAP + 全站文案打包压缩后的结果，
变量名全是 `We`、`aH` 这种。任何「智能」的正则批量替换都会在某天悄悄改坏东西。

所以采用**锚点替换**：每一处改动都对应一段**在整个文件中出现且仅出现一次**的字符串。
构建时逐个查找并替换，出现 0 次或 ≥2 次立即失败。

```js
add('error.rights', 'engine',
  'We("p",{class:"text-sans-18 text-white opacity-61"}," © All rights reserved ")',
  `We("p",{class:"text-sans-18 text-white opacity-61"},${q(` ${errorPage.rights} `)})`);
```

`tools/scanner.js` 负责在构建前扫描所有锚点的唯一性，测试里也有一份对应用例。
目前共 **75 处**（外壳 74 + 滚动节奏生成器 1）。

除锚点外，还有三类改动：

1. **故事数据外置**：引擎里 5 个内联数组（`smallLight`/`smallDark`/`big`/`lines`/`cases`）
   改成从新生成的 `_nuxt/story.data.js` 读取，内容由 `config/story.js` 编译而来。
2. **滚动节奏生成器整体替换**：引擎里的 `aH=n=>[{id:"1",scrollLength:n?100:50},...]`
   由 `config/scene.js` 重新生成。**默认配置下输出与原文件逐字节一致**，有测试锁定。
3. **主题注入**：`<style id="ns-theme">`，承载强调色和 `{line}` 的宽度/偏移 CSS 变量。

## 3. 关键技术决策

### 3.1 为什么不用 Tailwind 重新构建样式

`src/_nuxt/entry.BEbxiOYI.css` + `index.CeGRoErV.css` 是**已经 tree-shake 完的 Tailwind 产物**，
只包含原站用过的 **585 个类名**。写一个不存在的类不会报错，只会静默失效——
这是最容易埋雷的地方。

引入 Tailwind 重新构建意味着要还原原站的完整配置（自定义颜色、`--spacing:.1rem`、
`html{font-size:10px}` 的 1 单位 = 1px 约定、断点 `xs:320 md:768 lg:1024`），
风险和收益不成比例，也和「零依赖」冲突。

**选择**：`tools/cssclasses.js` 从 CSS 里解析出白名单，构建时校验所有类名，
未知类名直接失败并给相近建议（编辑距离）。需要任意数值时走 CSS 自定义属性：

```html
<span class="ns-line ns-w ns-t" style="--ns-w-lg:600px;--ns-w-xs:300px;--ns-tx-xs:-30%">
```

配套的 `@media` 规则由 `tools/theme.js` 注入。这样宽度和位移不再受编译产物限制。

### 3.2 强调样式：从斜体改成换色

原站用 The Seasons 斜体做强调。但**打包进来的两款字体都没有中文字形**，
中文会回退到系统字体，`<i>` 得到的是浏览器合成的伪斜体，字重和字形都是坏的。

**选择**：新增 `site.typography.emphasis`，四种模式：

| 模式 | 效果 |
|---|---|
| `accent`（默认） | 换成品牌色（深色背景 `#88aeff`，浅色背景 `#3762be`） |
| `gradient` | 渐变字，需同时作用于 `.char`（GSAP SplitText 会把文字节点拆开重排） |
| `italic` | 保留原斜体 |
| `none` | 不做任何强调 |

明暗由块所属场景决定：`KIND_TONE = { smallLight: 'light', smallDark: 'dark', big: 'dark', lines: 'dark' }`，
可以在单个块上用 `tone` 覆盖。

### 3.3 简写 DSL

原始文案是这样的（单块最长 1.2KB）：

```html
<span class="inline-block xs:mr-25 lg:mr-110 relative z-2">Through <i class="...">change</i>,</span>
```

**选择**：一套小型 DSL，`[[强调]]`、`{sz}`、`{line}`、`{icon}`、`{g}`……
外加 `{raw}…{/raw}` 逃生舱，任何 DSL 表达不了的场景都能直接写 HTML。
**一行配置 = 页面上的一行**，不用手写 `<br>`。

编译器（`tools/markup.js`）对未知 token、未闭合标签、非法数值全部**硬报错并指出位置**，
不做「尽力而为」的容错——静默产出坏页面比构建失败糟糕得多。

### 3.4 滚动位置表达式

原始位置是这种写在数组里的裸数字：`scrollStart: 100+150+300+250`。
`tools/positions.js` 把它换成结构化描述：

```js
at: { s: 11, base: 160 }   // 前 11 段之和（含第 11 段）+ 160
```

求值：`sum(s) + base + half/n + (isMobile?mobile:0) + (isTablet?tablet:0) + (innerHeight<850?short:0)`，
其中 `n = isMobile ? 2 : 1`。测试里锁定了**全部 17 个块 × 4 个位置**的原始数值能逐个还原。

这么做的价值：改 `scene.js` 里某一段的 `scrollLength`，所有引用它之后位置的文字块会**自动跟着移动**，
不用手工重算几十个数字。

### 3.5 404 页面

站内路由已经全死，任何拼错的地址都会落到 404，所以它必须能独立站住。
试了三种方案，前两种都不成立（相对路径失效 / Vue Router 把 `<base>` 当路由基址并触发
chunk 重载死循环），最终生成一个**零 JS 的独立页面**。详见 `README.md`。

需要 `site.meta.basePath` 配置正确，否则返回链接和内联字体会 404——
构建时会校验 `basePath` 必须以 `/` 开头和结尾。

## 4. 中文化

### 4.1 两边同时改

预渲染 HTML 和引擎 chunk 里的同一句话必须**同时**换掉，否则注水就会回退。
`tools/anchors.js` 里凡是同时出现在两个文件的文案，都成对列出。

有几组锚点长得几乎一样，靠 Vue 的 patch flag 参数区分——移动端菜单结尾是 `,-1)`，
错误页结尾是 `,32)`。上游自己还写错了大小写（菜单里是 `"Linkedin"`，错误页是 `"LinkedIn"`）。

### 4.2 意译而非直译

按约定做的是**中文语感重写**，不是逐词翻译。例如：

| 原文 | 译文 |
|---|---|
| The world is in constant flux | 世界始终在不断流变 |
| Don't feel lost, let's go Home | 别在这儿迷路，回首页看看 |
| Test, then iterate | 试验，然后迭代 |

首屏大字 `storytelling` 按约定**保留英文**（它是被 SplitText 逐字母动画驱动的视觉主体）。
`Light` / `Spirit` / `Sound` / `narrative.` 同理保留，中文放在陪衬行。

### 4.3 英文残留审计

写了两个扫描脚本，把两个 chunk 里所有「像人话」的双引号字符串全部过了一遍：

- 页面 chunk **干净**（只剩一个从不渲染的 prop 默认值 `Sample Small Text`）；
- 引擎 chunk 剩 140 条，全部是 Three.js/GSAP/Vue 的**库内部报错**、Tweakpane 调试面板标签、
  UA 检测正则（`Instagram`、`LinkedInBot`、`MacIntel`）、键名（`PageUp`）、Pinia 方法名——
  都不会出现在用户界面上；
- **真找到了两条漏网的**：404 页的 `Don't feel lost, let's go Home` 和 `© All rights reserved`。
  一并做成了配置项。

### 4.4 排版重调

中文和英文的行为完全不同：没有词间空格、可以在任意位置断行、字宽统一。
用 Playwright 量了**桌面 1600×900** 和 **iPhone 13（真实 UA）**下全部 17 个块的
包围盒、行数、视口溢出，据此调整了各块的宽度与偏移。

> 移动端设备判定读的是 `navigator.userAgent` **正则**，只把 viewport 改小、
> `is_mobile=True` 是骗不过它的——项目热区的标题只在 `isMobile || isRealTablet` 时渲染。
> 测试里必须用 `pw.devices['iPhone 13']` 的完整 UA。

发现并修掉的一类问题：装饰横线 `{line}` 原来只有一个宽度，桌面上 600px 的横线
在 390px 宽的手机上会横向溢出。现在 `w=600/300` 支持按断点分别给值，
五处受影响的横线都补了移动端宽度。

## 5. 构建与开发体验

| 命令 | 说明 |
|---|---|
| `npm run fetch-src` | 从快照仓库固定提交 `1412a9f` 取回 `src/`（70 个文件，11.1 MB） |
| `npm run build` | 全量构建，约 **0.16 秒**，70 个文件 |
| `npm run dev` | 监听 `config/` 与 `src/`，去抖 80ms，**进程内**重建（约 150ms）+ 浏览器自动刷新 |
| `npm run serve` | 静态预览，默认挂在 `site.meta.basePath` 下 |
| `npm test` | 220 项单元测试 |
| `npm run test:e2e` | 84 项真浏览器验收 |

**零 npm 依赖**：只用 Node 内置模块（`fs`/`path`/`http`/`child_process`）。CI 里不跑 `npm ci`。
`src/` 不入库（版权不属于本项目），`build` / `dev` / `test` 都挂了 `pre` 钩子，缺失时自动补拉。

热重载用的是 **400ms 轮询构建号**，不是 WebSocket——为了保持零依赖，
也省掉连接生命周期管理。配置写坏了进程不退出：打印中文报错、保留上一次可用的 `dist/`、
下次存盘自动恢复。

构建过程中新写的测试还**抓到了一个真 bug**：`build.js` 原来写的是
`site ? buildTheme(site) : {...}`，当 `normalizeSite` 因为配置错误抛异常时 `site` 是 null，
主题校验被整个跳过，破坏了「一次报出所有配置错误」的约定。
改成 `buildTheme(site || rawSite)` 后，两处配置同时写错能一次报出两条。

**无法自动验证的**：headless 用 SwiftShader 软件渲染，3D 场景实际观感、水晶折射、
滚动手感、音效都需要在真机上确认。

## 7. 三项视觉改版

模板落地之后又做了三处视觉重做。它们和前面的中文化不是一回事：中文化是「把内容抽成配置」，
这三项是「上游本来就不好看 / 本来就是坏的」。

### 7.1 加载页 —— 先修 bug，再谈好看

原本以为只是换个配色，解包之后发现克隆里有两个真问题。

**问题一：上游的揭幕动画从来没播放过。**
上游 `Preloader.vue` 监听 store 的 `setSceneLoaded`，触发时跑一条 GSAP 时间线 ——
圆形遮罩 `--reveal-radius` 从 `0vmax` 扩到 `200vmax`，1.2 秒后解锁滚动，完成后让 Vue
卸载节点。但克隆作者在 `index.html` 里手写了一段内联脚本 `hideReadyPreloader`：`load`
之后每 500ms 轮询，一旦 canvas 覆盖 80% 视口就把 `.preloader` 淡出并 `remove()`。
这段脚本抢在前面把节点摘走了 —— 揭幕动画不播，而且 Vue 后来仍持有该节点引用，桌面端会
稳定报 `TypeError: Cannot read properties of null (reading 'insertBefore')`。

修法是双向握手，不是简单删掉那段脚本（删掉的话 `.preloader` 永不卸载，
`setSceneLoaded` 也就永远不 dispatch）：

- 新运行时自己判定就绪（`loading.complete` + canvas 铺满 + 500ms 静默），然后调
  **组件自己的**揭幕函数，让上游那条时间线正常播完、Vue 正常卸载。
- 兜底脚本重写成只做 `opacity` 过渡 + 700ms 后 `visibility:hidden;display:none`，
  **绝不 `remove()`**。两边通过 `window.__nsPreState`（`live` / `revealing`）通气。

**问题二：真实进度在引擎包下载期间是 0。**
引擎自己的 `loading.progress` 要等 1.6 MB 的引擎包解析执行后才开始发，慢网下计数器能卡
十几秒。解法是加一段几百字节的引导脚本，按时间缓动 `0.5*(1-exp(-Δt/5200))` 往前推，
**上限 50%**；引擎起来后运行时读走引导值当地板，真实进度映射到 `[floor, 0.97]`，
`loading.complete` 之后线性冲到 100。数字全程单调不减，也不会先冲高再倒退。

还有个注水的坑：Vue 注水会把 `.ns-pre-val` 复位成 SSR 里的 `"0"`，所以 setup 末尾排了个
微任务 `Promise.resolve().then(paint)` 写回当前值。

**缓动本身返工过一次。** 第一版逐帧 lerp（`shown += (target-shown)*0.08`）在 6fps 的软件
渲染下慢得像坏了。改成按时间：`dt = clamp(t-prev, 0, 400)`，
`shown += (target-shown) * (1 - exp(-dt/τ))`，τ 常态 900ms、收尾 150ms。

配色是深蓝品牌渐变（`#00276e → #143a8a → #062969`）叠两团极光光斑。提示文案对比度调过
一轮：`rgba(255,255,255,.62)` 在三段渐变上是 6.11 / 5.04 / 6.13，最差 5.04:1 过 AA；
再淡一档（.56）就掉到 4.40，不够。

### 7.2 移动端菜单 —— 不是颜色不好看，是压根没有背景

用户原话是「黑不溜秋」。实测（390×664，iPhone 13 UA，打开态）：

```
backgroundImage : "none"
backgroundColor : "rgba(0, 0, 0, 0)"
backdropFilter  : "none"
```

看到的其实是底下的 3D 场景。根因是上游这条规则：

```css
.mobile-menu[data-v-89305177]{
  //background-image:url(./images/menu_back.jpg);
  //background-size:cover;
  //background-position:center
}
```

`//` 是 Sass 注释，在 CSS 里非法 —— 解析器遇到第一个 `//` 就把整条声明块判废。而且
`images/menu_back.jpg` 在克隆里根本不存在。这条坏规则在两处各有一份：`src/index.html`
的内联 `<style>` 和 `src/_nuxt/entry.BEbxiOYI.css`。没有去改那两处（锚点替换 CSS 很脆），
而是在 `#ns-theme` 里用 `.mobile-menu.mobile-menu` 重复类名抬高优先级覆盖。

两个实现细节值得记一笔：

- **噪点层用 `isolation: isolate` 关起来。** 噪点是 `::after` 加一个内联的
  `feTurbulence` SVG data URI，`mix-blend-mode: overlay`、`z-index: -1`。不加
  `isolation` 的话 `-1` 会捅穿到父级。
- **动画和 `backdrop-filter` 都由 `.opacity-100` 门控。** 菜单关着时是 `opacity:0` 但仍
  在 DOM 里，不门控的话 34 秒的极光动画和毛玻璃会一直在后台烧电。

验收是实拍像素：截图后在五个避开字形的位置采样，白字对比度最差 7.38:1。

### 7.3 水晶 —— 推翻了一开始的假设

一开始的计划写的是「重排 7 颗水晶的颜色」。解包之后发现这个描述是错的。引擎里有两张表：

```js
crystal: { … }          // 25 个键，静止态，7 颗共用
crystalHovers: [ … ]    // 7 条，悬停态，逐颗不同
```

消费代码（`class Jh` 的 `set isHovered`）把 `crystalHovers[i]` 的每个键拿出来，用
`X.settings.crystal[key]` 作为**弹簧静止值**建一根弹簧，hover 时朝
`crystalHovers[i][key]` 拉过去，松开再弹回来。也就是说：

- 上游 `crystal.baseColor` 是纯白、`envRefraction` 是 0 → **不 hover 时 7 颗一模一样，
  全是白的**。这是 95% 时间看到的样子。
- 那 7 个漂亮颜色只在 hover 时出现，移动端根本没有 hover。

所以改的重点变成两件事：让静止态本身就好看（冷蓝底色 `#EEF4FF`、边缘光 `#DCE7FF`、
`envRefraction` 0 → 0.22、开一点虹彩），以及把 7 个 hover 色相重排。上游 7 色里有 4 颗挤在
128°/154°/167°/187°，其中两颗饱和度只有 21% 和 56%；aurora 预设重排成
`[45, 222, 138, 312, 265, 186, 96]`，饱和度统一 0.82，相邻至少差 30°。

**踩过的坑：`peaksFactor` 不是「棱峰锐度」。** 着色器里是
`vGlassColor = mix(baseColor, peaksColor, clamp(_peaks * peaksFactor, 0, 1))` ——
调高它是拿 `peaksColor` 盖掉 `baseColor`，跟「让棱更利」的直觉正相反。三套预设里原本
各有一条 `peaksFactor` 变换，全部删掉了。

「不动」组一共 8 个参数：`distancesFactor`、`convexityFactor`、`concavityFactor`、
`uvShiftFactor`、`resetDistances`、`peaksFactor`、`colorFactor`、`decayFactor`。
它们直接乘在 glb 烘焙进去的顶点属性上，改了就是错位。

三个必须守住的形状约束：

- `crystalHovers` 必须**恰好 7 条** —— 消费者是
  `for (let e = 0; e < X.settings.crystalHovers.length; e++)`。
- 类型分派用 `instanceof Re`（THREE.Color），颜色必须序列化成 `new Re(十进制)`，
  写成字符串会被当数值弹簧处理。
- 索引 2 那条上游本来就少一个 `resetDistances`（24 键，其余 6 条 25 键）。补上去会多建
  一根弹簧，所以原样保留；`buildCrystals` 遇到「给某颗补了上游没有的键」会告警。

几何模型没换。每个 `crystalN.glb` 是 3 网格 / 4 节点：`Root`、`Cube`（带
`_peaks`/`_convexity`/`_thickness`/`_concavity` 四组顶点属性）、`Icon`（**里面嵌着各家
客户的 logo**）、`ConvexHull`，全部 Draco 压缩。换几何要重跑上游的烘焙流程。

### 7.4 一个验不了的东西

无 GPU 环境下 WebGL 走 SwiftShader，实测 6.2 fps。更要命的是引擎写进 Pinia store 的
`getIceCubePositionByIndex` 恒为 0 —— 7 颗水晶的热区 watcher 永远不触发，`.case-debug`
始终 `display:none`，滚动到哪都进不去水晶那一屏。对原始克隆跑同一个探针，输出一字不差，
说明这是环境限制而不是本次改造引入的回归。

试过的路子都失败了：`canvas.drawImage` 回读 WebGL 画布拿到全 0（渲染器没开
`preserveDrawingBuffer`）；改用截图 + 像素采样又因为热区 rect 全 0 采不到点；桌面/移动端
0.58–0.90 多档滚动扫描都进不去。

结论写在这里，也写进了 README：**水晶好不好看必须真机验收**，自动化只能保证参数正确、
构建通过、控制台 0 报错。

## 8. 已知限制

- **水晶数量固定 7 个**，相机时间线、材质参数、流体效果都是原站硬编码，无法配置。
  替换模型必须是 Draco 压缩的 `.glb`，包围盒尺寸相近。
- **只支持中文单语言**，没有做 i18n 切换。
- **没有做 `?debug=1` 调试浮层**（按约定砍掉），但单个块上的 `debug: true` 仍可用。
- **站内路由依然是死的**（上游 chunk 缺失），所有内页入口都是外链。
- `src/_nuxt/*` 的文件名带内容哈希，如果将来重新抓取上游快照，
  `tools/paths.js` 里的文件名和 `tools/anchors.js` 里的锚点都要重新对齐——
  这也是为什么它们被集中放在两个文件里。
- **字体和素材的授权问题没有解决**，也无法在代码层面解决，见 `README.md` 文首。
